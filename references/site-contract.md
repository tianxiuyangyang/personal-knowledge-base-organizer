# 知境网站契约：不可丢失的体验与技术边界

## 目标

这是一个本地优先的单页个人知识库。它的关键不是文件列表，而是让用户通过首页仪表盘和可编辑网络，在“输入 → 连接 → 行动 → 回顾”之间切换。

## 固定页面与入口

| 页面/入口 | 作用 | 关键行为 |
|---|---|---|
| 知识中枢 | 首页仪表盘 | 今日聚焦、任务、最近沉淀、知识地图核心项目入口 |
| 收件箱 | 快速捕捉 | 添加、删除、计数更新 |
| 每日记录 | 记录与反思 | 勾选清单、日终复盘表单 |
| 周度回顾 | 系统校准 | 清空输入、审视行动、复盘与校准入口 |
| 活跃项目 | 目标推进 | 项目卡片与完成进度 |
| 长期领域 | 长期责任 | 健康、职业、财务、关系、生活等领域卡片 |
| 知识地图 | 主项目/主界面 | 无限画布、节点和边、编辑面板、全屏沉浸 |
| 资源库 | 复用知识 | 方法、思考、书籍、框架等知识卡片 |

## 视觉基因

- 侧边栏：深墨绿色/蓝黑色；主内容：温暖纸张色。
- 强调色：橄榄绿与低饱和金色；节点类型再补充蓝紫、砖红、青灰。
- 字体层级：中文衬线字体用于标题和叙事，清晰无衬线字体用于交互。
- 细边框、圆角卡片、微弱阴影、纸张颗粒和密点网格表达精致但非浮夸的质感。
- 首页的知识地图入口必须在首屏主要内容中、位于普通任务模块之前。

## 无构建依赖

模板仅使用：

- `index.html`
- `styles.css`
- `app.js`
- 浏览器 Canvas、Fullscreen API、LocalStorage、原生 DOM API

不要默认添加 React、Vue、npm、后端、数据库或鉴权。这些会违背“打开即可用”的部署方式，并非本项目所需。

## 图谱数据模型

`app.js` 中的网络模型应保持以下概念：

```js
{
  nodes: [
    { id, title, body, type, x, y, r }
  ],
  edges: [[sourceId, targetId]]
}
```

节点类型：`idea`、`project`、`method`、`area`、`resource`。每个类型必须有颜色、标签名称与可区分的视觉表现。节点的屏幕位置由 world coordinates（`x`, `y`）加上 view transform（`view.x`, `view.y`, `view.scale`）推导，不能把浏览器坐标直接持久化。

## 图谱交互验收清单

- 空白处 pointer drag 平移画布。
- 滚轮以鼠标位置为锚点缩放；缩放有上下限。
- 点击节点选中，并将数据填充进右侧编辑器。
- 拖动节点改变 world coordinates。
- 空白处双击或“新建节点”创建节点。
- 编辑标题、类型、正文、连接对象后保存。
- 删除节点时同时清除所有关联边。
- “视图归位”将完整网络纳入可见范围。
- 首页和图谱页都能触发 Fullscreen API；`Esc` 退出后重新计算 Canvas 尺寸。
- 图谱状态更新后写入 LocalStorage，刷新后还原。

## 文件修改责任

| 修改内容 | 主要文件 |
|---|---|
| 结构、页面文案、控制 ID | `index.html` |
| 颜色、布局、响应式、全屏视觉 | `styles.css` |
| 状态、图谱、任务/收件箱/命令面板交互 | `app.js` |

如果改动任一 DOM ID、节点字段、LocalStorage key 或页面 ID，必须同步检查全部引用。不要只改视觉层。
